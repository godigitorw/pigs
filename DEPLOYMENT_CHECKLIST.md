# Render Deployment Checklist

Use this checklist to ensure a smooth deployment to Render.

## Pre-Deployment Checklist

### Code Preparation
- [x] `render.yaml` blueprint created
- [x] `build.sh` script created and executable
- [x] `requirements.txt` verified and complete
- [x] `runtime.txt` specifies Python 3.13.0
- [x] `.env.example` created with all required variables
- [x] Settings updated for Render compatibility
- [x] CSRF trusted origins include `*.onrender.com`
- [x] Media files configuration added
- [x] URL configuration updated for media serving

### Git Repository
- [ ] All changes committed to git
- [ ] Code pushed to GitHub/GitLab/Bitbucket
- [ ] Repository is accessible (public or Render has access)
- [ ] Main/master branch is up to date

### Security Review
- [ ] No sensitive data in code (passwords, API keys, etc.)
- [ ] `.env` file is in `.gitignore` (should NOT be committed)
- [ ] `DEBUG=False` will be set in production environment variables
- [ ] Strong `SECRET_KEY` will be generated by Render
- [ ] Default admin password will be changed after first login

## Deployment Steps

### 1. Create Render Account
- [ ] Sign up at https://render.com/
- [ ] Verify email address
- [ ] Complete profile setup

### 2. Connect Git Repository
- [ ] Go to Render Dashboard
- [ ] Click "New +" → "Blueprint"
- [ ] Connect GitHub/GitLab/Bitbucket account
- [ ] Authorize Render to access repositories
- [ ] Select the Pigs repository

### 3. Configure Blueprint
- [ ] Render detects `render.yaml` automatically
- [ ] Review services to be created:
  - Web Service: `pigfarm`
  - PostgreSQL: `pigfarm-db`
- [ ] Verify build command: `./build.sh`
- [ ] Verify start command: `cd pigfarm && gunicorn pigfarm.wsgi:application`

### 4. Set Environment Variables
- [ ] `SECRET_KEY` - Let Render auto-generate
- [ ] `DEBUG` - Set to `False`
- [ ] `ALLOWED_HOSTS` - Will update after getting URL
- [ ] `DATABASE_URL` - Auto-set from database service
- [ ] `RENDER` - Set to `true`
- [ ] `PYTHON_VERSION` - Set to `3.13.0`

### 5. Deploy
- [ ] Click "Apply" to start deployment
- [ ] Monitor build logs for errors
- [ ] Wait for deployment to complete (may take 5-10 minutes)
- [ ] Check for successful deployment status

## Common Issues & Solutions

### Build Fails
**Issue**: Build script errors
- [ ] Check `build.sh` has execute permissions
- [ ] Review Render build logs for specific errors
- [ ] Verify all dependencies in `requirements.txt`

### Database Connection Fails
**Issue**: Can't connect to PostgreSQL
- [ ] Verify `DATABASE_URL` is set correctly
- [ ] Check database service is running in Render
- [ ] Ensure database and web service in same region

### Static Files 404
**Issue**: CSS/JS not loading
- [ ] Verify `collectstatic` ran in build logs
- [ ] Check `STATIC_ROOT` and `STATIC_URL` in settings
- [ ] Confirm WhiteNoise middleware is active

### App Won't Start
**Issue**: Service shows "Deploy failed"
- [ ] Check start command is correct
- [ ] Review application logs in Render
- [ ] Verify migrations completed successfully
- [ ] Check for Python errors in logs

### Slow First Load
**Issue**: App takes 30+ seconds to respond initially
- [ ] Normal behavior for free tier (app sleeps after inactivity)
- [ ] Subsequent requests will be fast
- [ ] Consider upgrading to paid plan for 24/7 uptime

## Backup Strategy

### Free Tier
- [ ] Manually export database periodically:

- [ ] Download and store backups externally
- [ ] Document backup schedule

### Paid Tier (Recommended for Production)
- [ ] Enable automatic PostgreSQL backups
- [ ] Test restore procedure
- [ ] Set up backup monitoring
- [ ] Document recovery procedures
